# 第一部分：怎么看一次实验的结果

## 1.1 一次实验的完整链条（你缺了哪一环就会答不上）

```
跑命令 → 看 stdout 前 20 行 → 看逐 epoch 日志(tsv) → 看曲线形状 → 挑 best epoch → 对比论文 → 判断复现是否成立
  ①          ②                    ③                    ④              ⑤            ⑥              ⑦
```

大多数人只做 ①②⑦，所以一被追问就崩。**③④⑤ 才是能证明"我懂"的地方。**

## 1.2 看日志：四个检查点（30 秒能看完，但要会看）

打开 `logs/xxx.tsv`，依次看四件事：

| # | 看什么 | 正常 | 异常 → 说明什么 |
|---|---|---|---|
| 1 | **HR 是否整体上升** | 前 20% epoch 快速上升 | 一开始就 0.8 → **数据泄漏**（测试集混进训练了） |
| 2 | **什么时候达峰** | 中后段达峰后小幅波动 | 最后一轮还在猛涨 → **训练不够，加到更少 epoch 是浪费**；换更多 epoch |
| 3 | **达峰后是否回落** | 波动 < 0.01 | 明显回落 → **过拟合**，要早停 / 加正则 / 减容量 |
| 4 | **HR 与 NDCG 是否同步** | 同向变化 | HR 涨但 NDCG 不涨 → **命中率提高但排序质量没提高**（把对的东西排得靠后了）；NDCG 涨但 HR 不涨 → 少数用户排得极好，多数没命中 |

**我的实测（可以当例子讲）**：LightGCN 在 ML-1M 上
```
epoch  10 | HR 0.5361 | NDCG 0.2937
epoch  40 | HR 0.6497 | NDCG 0.3725
epoch 220 | HR 0.7149 | NDCG 0.4265   ← 达峰
epoch 300 | HR 0.7099 | NDCG 0.4265   ← 270–300 波动 0.0023
```
→ 达峰后波动 0.0023 < 0.01，**不是过拟合，是收敛**。所以我说"进入平台期，不存在没训够"。

## 1.3 看曲线：三种形状对应三种诊断

| 形状 | 图长什么样 | 诊断 | 动作 |
|---|---|---|---|
| **欠拟合** | 训练 loss 和验证指标**都还高**，且都在下降 | 模型容量不够 / 训练太少 / lr 太大导致震荡 | 加 epoch、加维度、降 lr |
| **健康** | loss 单调降，验证指标升到平台后**平** | 正常收敛 | 停在平台期，取 best epoch |
| **过拟合** | loss 继续降，验证指标**掉头向下** | 记住了训练集 | 早停、加 dropout/reg、减维度 |

**关键**：判断依据一定是**两条线**（训练 loss + 验证指标），只看一条必错。

## 1.4 看指标：HR 与 NDCG 到底在说什么

| 指标 | 算什么 | 什么时候会骗你 |
|---|---|---|
| **HR@10** | 正确答案有没有进前 10（0/1 的平均） | 只关心"有没有"，不关心"排第几"；正样本容易区分时虚高 |
| **NDCG@10** | 进了前 10 的话，排得越靠前分越高（1/log2(rank+1)） | 对排位敏感，但对"排第 11"和"排第 1000"一样算 0 |
| **Recall@20** | 全量候选里捞回多少 | 和 HR 在 leave-one-out 下几乎等价（只有 1 个正确答案） |

**必答的一句话**：
> 「leave-one-out 每个用户只有 1 个正样本，所以 HR 和 Recall 在这里是一回事；NDCG 额外惩罚排位靠后。两个一起报，是因为 HR 高可能是靠『蒙进前 10』，NDCG 才反映排序质量。」

## 1.5 「复现成功」的三档标准（导师一定会问）

| 档 | 标准 | 我这次的成绩 |
|---|---|---|
| ❌ 不成立 | 相对趋势都不对（如 MLP > NeuMF） | — |
| ✅ 成立 | **相对趋势一致** + 绝对值在千分位内 | NeuMF 0.6904 vs 论文 0.688（+0.0024）；SASRec 0.8295 vs 0.8235（+0.0060） |
| ✅✅ 强复现 | 上面两条 + 3 次运行方差小 + 消融能对上 | SASRec 3 seed 标准差 0.0014 |

**如果差得多怎么办（必准备的答法）**：按这四条归因，别笼统说"实现差异"——
1. **框架不同**（TF→PyTorch 的实现细节）
2. **训练预算**（论文做网格搜索，我只固定一组超参）
3. **数据版本/切分**（我们是 3,706 物品，论文 5-core 后 3,416）
4. **论文自己的问题**（图里读数误差、在测试集上挑最优 epoch）

# 第二部分：怎么调参

## 2.1 参数地图：五类，敏感度从高到低

| 类 | 参数 | 敏感度 | 调大 → | 调小 → | 我的实测值 |
|---|---|---|---|---|---|
| **优化** | **lr** | ★★★★★ | 震荡、发散 | 几十轮不收敛 | 1e-3 |
| | batch_size | ★★★ | 梯度稳、泛化略差、占显存 | 噪声大、慢 | NCF 256 / LightGCN 2048 / SASRec 128 |
| **容量** | embedding 维度 | ★★★★ | 表达强、易过拟合 | 表达不足 | 64（LightGCN）/ 50（SASRec） |
| | 层数 / block 数 | ★★★ | 深了过平滑（图）/ 退化（序列） | 学不到高阶 | 3 层 / 2 block |
| **正则** | L2 / weight_decay | ★★★ | 欠拟合 | 过拟合 | 1e-4 |
| | dropout | ★★★ | 欠拟合、收敛慢 | 过拟合 | 0.2（SASRec） |
| **目标** | 负采样比例 | ★★★ | 学到更多"不喜欢"，但慢 | 区分能力弱 | NCF 1:4 / 图与序列 1:1 |
| | 序列长度 maxlen | ★★ | 保留更长历史、慢 | 丢长期兴趣 | 200 |
| **预算** | epochs | ★★★★ | 白跑 / 过拟合 | 欠拟合 | 见平台期 |

## 2.2 调参决策树（从现象到动作，照着做）

```
现象 A：验证指标一直上不去，训练 loss 也不降
  → 先排查代码/数据（不是调参能救的）
     ① 负样本有没有真的排除正样本？② 评估时有没有遮掉训练集？
     ③ 学习率是不是大到发散了？（把 loss 打印出来看，NaN/爆掉就是）

现象 B：训练 loss 降，验证指标不涨
  → 过拟合
     ① 先加 dropout（序列 0.2 / 图 0.0–0.1）
     ② 再加 L2（1e-4 → 1e-3）
     ③ 还不行就减容量（维度 64 → 32）

现象 C：两条线都还在降/升，没到平台
  → 欠拟合
     ① 加 epoch（这是最便宜的）
     ② 加维度（64 → 128，但注意过拟合风险）
     ③ lr 太小的话，提到 1e-3

现象 D：指标波动大，三个 seed 差很多
  → 训练不稳定
     ① 降 lr 一半
     ② 加 batch（128 → 256/512）
     ③ 这是"结论不可信"的信号，不要忽略
```

## 2.3 调参的四条纪律（做不到就等于白调）

1. **单变量**：一次只动一个参数，其他全固定。同时动 lr 和维度，赢了也不知道是谁的功劳。
2. **固定 seed**：用 `--seed` 固定随机性，否则差异分不清是参数还是运气。
3. **落盘**：每次实验的配置 + 逐 epoch 指标写进文件（我这次是 `logs/{model}_{dataset}_{tag}.tsv` + `args.txt`）。
4. **记录最优**：报 **best-HR epoch 那一行的 HR 和对应 NDCG**，不要 HR 取最优、NDCG 也取最优（那是 cherry-picking，导师一眼看穿）。

## 2.4 我的三组真实配置（可以直接背下来）

**NCF（8 月，factor 8）**
```
batch 256 / lr 1e-3 / Adam / 1:4 负采样 / 50 epoch
→ GMF 0.640 / MLP 0.675 / NeuMF 0.690（论文 0.688）
每 epoch 26–38 秒
```

**LightGCN（10 月，ML-1M leave-one-out）**
```
dim 64 / layers 3 / lr 1e-3 / reg 1e-4 / batch 2048 / 300 epoch
→ HR@10 0.7149 @ epoch 220（270–300 波动 0.0023）
embedding 只有第 0 层，唯一可训练参数；BPR + softplus(neg−pos)
约 8–10 秒/epoch（5070 Ti）
```

**SASRec（10 月，ML-1M，3 seed）**
```
hidden 50 / blocks 2 / heads 1 / lr 1e-3 / batch 128 / maxlen 200 / dropout 0.2 / 200 epoch
→ HR@10 0.8295 ± 0.0014（论文 0.8235）
约 2 分钟跑完 200 epoch
```

## 2.5 如果导师问「你怎么把 SASRec 再往上调」

**不要说"调调看"**。给一个有序方案 + 一个预期：

| 顺序 | 动作 | 预期 | 风险 |
|---|---|---|---|
| 1 | maxlen 200 → 256 | +0.001~0.003 | ML-1M 平均序列 163，收益有限 |
| 2 | hidden 50 → 64 | +0.002~0.005 | 参数变多，小数据易过拟合 |
| 3 | dropout 0.2 → 0.3/0.5 | 视情况 ±0.003 | 太大欠拟合 |
| 4 | 负采样 1 → 4 个/步 | +0.003~0.008 | 训练时间 ×2 |
| 5 | 加 lr warmup + 余弦退火 | +0.001~0.003 | 要改训练循环 |

**收口句**（这句最值钱）：
> 「但我的判断是，这些加起来大概率到不了 0.84。论文本身在 ML-1M 就是 0.8235，我们再往上调，边际收益已经小于『换数据集验证结论是否成立』的收益了。所以我把力气放在协议和第二个数据集上，而不是刷这一个数。」

**这句话同时证明三件事**：你懂调参、你知道边际收益、你知道研究该往哪走。

# 第三部分：常见错误清单（自查）

| 错误 | 后果 | 怎么避免 |
|---|---|---|
| 在测试集上挑最优 epoch | 数字虚高，被问就穿帮 | 用验证集挑，测试集只报一次 |
| HR 取最优 epoch、NDCG 取另一个 epoch 最优 | cherry-picking | 同一行取两个数 |
| 只报单次运行 | 方差未知，不可信 | 3 seed 取均值±std |
| 训练时负样本撞到正样本不排除 | 指标虚高 | 采样时查 `pos_by_user` |
| 评估时没遮掉训练已交互物品 | 严重虚高 | 候选集里剔除已交互 |
| 拿不同候选集的数字对比 | 结论整个错 | 钉死候选集 |
| 改完模型忘记改 `args.txt` | 复现不了自己的结果 | 每次运行自动落配置 |
| 只看最后一个 epoch | 可能是过拟合后的坏点 | 取 best + 看平台期 |

## 一句话总结这一整份

> **看结果看的是「趋势、平台、方差」三件事；调参调的是「欠拟合与过拟合之间的那条线」；而所有数字的可信度，取决于评审口径有没有钉死。**
