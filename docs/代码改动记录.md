# 对官方实现的改动记录（诚实性说明）

> 复现的原则：**改代码必须留痕**。凡是与官方仓库不同的地方都记在这里，并在报告中说明对结果的可能影响。

## 1. `pmixer/SASRec.pytorch`（SASRec 的 PyTorch 移植，非论文作者原始 TF 实现）

上游：https://github.com/pmixer/SASRec.pytorch（commit `b253407`）

| 改动 | 位置 | 原因 | 对结果的影响 |
|---|---|---|---|
| 新增 `--seed` 参数 | `python/main.py` 参数区 | 上游未设随机种子，无法做「3 次运行取均值/方差」 | 无（只控制随机性，不改模型） |
| 新增数据集 `ml-1m-all` | `python/data/ml-1m-all.txt` | 上游自带的 `ml-1m.txt` 已剔除出现 <5 次的 290 个长尾物品（3,416 个物品）；为与 NCF 的 3,706 物品空间对齐，从 NCF 官方切分重建 | **有**：候选集物品空间更大（3706 vs 3416），理论上任务更难。这是为了协议对齐做的主动选择 |
| 未改模型/损失/评估 | — | 保证复现的是论文方法 | — |

### 数据一致性校验（`data/build_ml1m_seq.py` 输出）

```
train=994169 test=6040 total=1000209
users=6040 items=3706
写出 ml-1m-all.txt 行数=1000209
前5物品频次(应=3428/2991/2990/2883/2672): [3428, 2991, 2990, 2883, 2672]
频次<5的物品数(应=290): 290
去掉<5频次物品后行数(应=999611): 999611     ← 与上游官方预处理版精确相等
序列长度 min/max/median: 20 2314 96
```

> 「我的重建数据剔掉长尾物品后 = 上游官方文件行数」——这一条是「同一份原始数据」的直接证据。

### 已知协议差异（必须说明）

上游 `data_partition` 取 `User[u][:-2]` 为训练、`[-2]` 为验证、`[-1]` 为测试。
NCF 的 leave-one-out 协议**没有验证集**（除最后一条外全部用于训练）。
→ SASRec 每个用户少用 1 条训练数据：6,040 / 1,000,209 ≈ **0.6%**。
验证集只用于选出最优 epoch，所有报告结果都来自测试集。

## 2. `gusye1234/LightGCN-PyTorch`（LightGCN 的 PyTorch 复现）

上游：https://github.com/gusye1234/LightGCN-PyTorch（commit `947ca2b`）

**没有直接使用上游的 `dataloader.py` / 训练循环**，原因：

- 上游只支持 `gowalla / yelp2018 / amazon-book / lastfm` 四个数据集，且要求它们各自的 `train.txt` 格式；
- 上游的 `utils.py` 评估是**全量物品排序**（排除训练交互），而 NCF 论文/官方代码是**1 正 + 99 负 = 100 候选**；
- 两种评估口径不能直接比较（见报告第 4 节）。

因此 `lightgcn/lightgcn_ml1m.py` 是**按上游 `model.py` 逐项复制模型与损失**、并从零编写数据加载与评估的单文件实现：

| 组件 | 来源 | 是否与上游一致 |
|---|---|---|
| 对称归一化邻接 `D^-1/2 A D^-1/2` | 上游 `dataloader.getSparseGraph` | ✅ 一致 |
| 第 0 层仅 ID 嵌入、无特征变换/无激活 | 上游 `model.LightGCN.computer` | ✅ 一致 |
| K 层传播 + 层组合取均值（含第 0 层） | 上游 `computer()` | ✅ 一致 |
| BPR loss = `softplus(neg - pos)` + `reg·‖e0‖²` | 上游 `bpr_loss` | ✅ 一致 |
| 初始化 `N(0, 0.1)` | 上游 `__init_weight` | ✅ 一致 |
| 数据加载 / 评估 | **自写** | 改为与 NCF 一致的 leave-one-out + 100 候选 |
| 超参 | dim 64 / 3 层 / lr 1e-3 / reg 1e-4 / batch 2048 | 上游 config 默认 |
| 训练轮数 | 300（上游 ML-1M 未提供，官方其他数据集用 1000） | ⚠️ 较少，见报告「复现局限」 |

> 为什么要自写：**统一评测口径**是这次工作的核心目标。用上游全量排序的评估，结果无法与 NCF 同一张表比较。
