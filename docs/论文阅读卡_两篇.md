# 卡 1：SASRec — Self-Attentive Sequential Recommendation

**Kang & McAuley, ICDM 2018**

## 第 1 页 · 问题

**一句话**：已有的序列推荐模型，要么假设「最近几个物品决定下一次点击」（MC 类），要么把整段历史压成一个定长隐向量（RNN 类）——前者看不见长期偏好，后者在长序列上会遗忘。

- MC（FPMC、Caser 等）：只依赖最近 L 个物品，**L 一长就稀疏、一短就丢信息**，本质是马尔可夫假设；
- RNN（GRU4Rec）：理论上能建模任意长历史，但**隐状态容量固定**，且训练难并行；
- CNN（Caser）：用卷积抽局部转移模式，感受野受限，需要堆很多层。

**论文要回答的问题**：能不能只靠**注意力**，让模型自己决定每一步该看历史的哪几个位置？

## 第 2 页 · 方法

四个组件，每个都有明确动机：

| 组件 | 做什么 | 为什么 |
|---|---|---|
| **因果自注意力**（causal / 单向 mask） | 每个位置只 attend 到它之前的位置 | 预测「下一个」时不能偷看未来；mask 掉当前位置及之后 |
| **绝对位置嵌入** | 把位置 1,2,3… 编码进输入 | 自注意力本身对顺序无感知，位置信息必须显式给 |
| **残差 + LayerNorm** | 每个 block 后接残差和归一化 | 深层网络训练稳定（直接照搬 Transformer） |
| **共享物品嵌入** | 输入嵌入和输出投影**共用同一个矩阵** | 大幅减参、缓解过拟合；论文实验证明共享比不共享好 |

- 训练目标：**二分类**（下一个物品是正样本 vs 随机负样本），每步采 1 个负样本，用 BCE；**不是** softmax 全量分类（数据大时算不动）；
- 丢弃：训练时对输入序列做**随机丢弃物品**（类似 dropout 数据增强）；
- 关键设计选择：**block 数 2、头数 1**——论文附录明确说层数加到 4 反而退化，因为数据规模撑不住。

## 第 3 页 · 实验

- 数据集：Amazon Beauty / Sports / Toys + **MovieLens-1M**；
- 协议：**leave-one-out**（每用户最后一条为测试、倒数第二条为验证）+ **1 正 + 100 负**候选 + HR@10 / NDCG@10；
- 对照：POP、MC、GRU4Rec、Caser 等；
- **ML-1M 报告值：HR@10 0.8235 / NDCG@10 0.5958**；
- 消融：证明「因果 mask」「位置嵌入」「嵌入共享」「残差」每一项都必要；注意力权重可视化显示模型会**跳过无关的近期物品**去关注更早的相关物品——这是论文最直观的卖点。

## 第 4 页 · 局限（方法本身，不是复现问题）

1. **只用用户自己的序列**，完全用不到其他用户的高阶协同信号——对交互极少的用户几乎无解；
2. **maxlen 硬截断**（论文 200）：更长历史直接丢；ML-1M 平均序列长 163.6，已有相当比例用户被截；
3. **绝对位置编码**对不规则时间间隔不敏感——用户的「三天前」和「半年前」被当成同样的相邻位置；
4. **训练目标与评估目标不一致**：训练是逐位置二分类，评估只测最后一位；
5. **冷启动**（新用户无序列）失效；
6. 后续被反复指出的：单层注意力头 + 小数据下，**收益有一部分来自「嵌入共享」这种正则化技巧**而不是注意力本身。

**和后续工作的关系**：BERT4Rec 把单向 mask 换成双向 + 完形填空；S³-Rec 加自监督；LLM4SBR 把语义先验接进来。**这条线的共同问题始终是「序列之外的信号怎么用」**——这正是我下一步想做的。

# 卡 2：LightGCN — Simplifying and Powering Graph Convolution Network for Recommendation

**He, Deng, Wang, Li, Zhang, Wang, SIGIR 2020**

## 第 1 页 · 问题

**一句话**：NGCF 把 GCN 原封不动搬到用户—物品二部图上，但 GCN 是为**属性图节点分类**设计的，其中两个组件在协同过滤里根本不该存在。

- GCN 的传播规则里有两个部件：**特征变换矩阵 W** 和**非线性激活 σ**；
- 它们存在的理由：属性图的节点带语义特征，需要一个可学习的空间映射；
- 但协同过滤的节点**只有 ID 嵌入、没有语义特征**——没有「可变换的输入」；
- 所以问题变成：**把这两个部件删掉会怎样？**

## 第 2 页 · 方法

三件事，全部围绕「少即是多」：

1. **轻图卷积**：只保留对称归一化的邻域加权求和
   `e_u^(k+1) = Σ_{i∈N(u)} 1/√(|N(u)||N(i)|) · e_i^(k)`
   没有 W、没有 σ；
2. **层组合**：最终表示是各层的**加权和**（权重固定 1/(K+1)），而不是 NGCF 的拼接 —— 这一步天然保留了第 0 层的自身信息，类似残差，能缓解过平滑；
3. **训练**：唯一可训练参数是**第 0 层的用户/物品 ID 嵌入**，用 **BPR 成对损失**（+ L2 正则）。

消融结论（论文最硬的一页）：
- 只删 W → 性能**升**；
- 只删 σ → 性能**升**；
- 两个都删 → 多数数据集最好。
→ **GCN 里对协同过滤真正有效的成分，只有邻域聚合本身。**

## 第 3 页 · 实验

- 数据集：**Gowalla / Yelp2018 / Amazon-Book**（随机切分，非 leave-one-out）；
- 指标：Recall@20、NDCG@20；
- **Gowalla Recall@20：MF 0.1291 → NGCF 0.1570 → LightGCN 0.1830**，相对 NGCF 提升约 16.6%，三个数据集平均提升约 16%；
- 参数量与训练时间显著低于 NGCF（少了 W 矩阵）；
- 超参分析：层数 **3 层左右最优**，再深就过平滑；embedding 维度 64 足够。

## 第 4 页 · 局限（方法本身）

1. **只用 ID 交互**，无侧信息 → 冷启动失效；
2. **静态图**：不建模时间，用户兴趣演化看不见（这正好是 SASRec 的地盘）；
3. **过平滑**是结构性的，只能靠 2–4 层 + 层组合缓解，高阶信号拿不全；
4. **均匀负采样 + BPR** → 大量假负例；后续工作（如 RecSys 2021 起的难负采样）专门打这一点；
5. **推理要对全量物品算分**，线上成本高（点积 + ANN 可缓解，但多层传播的收益在线上往往被牺牲掉）；
6. **归一化设计本身被复盘过**：RecSys 2024 的 *Revisiting LightGCN* 指出对称归一化在理论上不自洽并给出修正；
7. 后来 SGL / SimGCL 等工作说明：**LightGCN 的收益很大一部分可以用「自监督正则」解释**，图结构本身未必是关键。

## 两篇放在一起，得到的一句判断

> **SASRec 强在「顺序」，LightGCN 强在「高阶协同」，两者都缺对方那一半。**
> 我的复现结果（同一协议下 SASRec 明显高于 LightGCN/NCF）说明：在 ML-1M 这种中等密度数据上，**顺序信号比高阶协同更值钱**。
> 下一步想验证的正是这个判断的边界——在更稀疏的数据上，图那边的收益会不会反超。
