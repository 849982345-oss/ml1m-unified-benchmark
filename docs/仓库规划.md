# 代码仓库规划

> 目标：**每复现一篇论文，只需要写一个模型文件 + 一行注册**。数据、评估、日志、出图全部复用。

---

## 一、目录结构

```
ml1m-unified-benchmark/
├── README.md                 结果表 + 协议 + 复现命令（导师第一屏看这里）
├── run.py                    统一入口：--model bpr_mf / ngcf / lightgcn / ...
├── common/                   共用层（改这里会影响所有模型，慎改）
│   ├── data.py               ML-1M 加载 + 断言校验（100 候选、6040 用户）
│   ├── eval.py               唯一评估实现：HR@10 / NDCG@10 + 逐 epoch 日志
│   └── report.py             一键汇总：扫全部日志 → summary_all.json + 对比图
├── models/                   一模型一文件
│   ├── bpr_mf.py             BPR-MF（强基线）
│   ├── ngcf.py               NGCF（带 W 和 σ 的图卷积）
│   └── lightgcn.py           LightGCN（去掉 W 和 σ）
├── sasrec/                   SASRec（序列，上游移植 + 改动说明）
├── runs/                     实验结果（自动生成，git 里保留 tsv + config）
│   └── <model>/<tag>/
│       ├── metrics.tsv       epoch  HR@10  NDCG@10
│       └── config.json       当次所有超参 + 数据规模
├── figures/                  图（由 report.py 生成，不手工改）
│   ├── bars_all.png          全模型对比柱状图
│   └── curves_all.png        训练曲线
├── results/
│   ├── summary_all.json      各模型 best-HR 汇总（自动生成）
│   └── stats_runs.json       多次运行的均值/标准差
└── docs/                     报告、路线图、改动记录、现场材料
```

**为什么这样分**：
- `common/` 是**协议的唯一实现**。任何人想看"你到底怎么评估的"，只需要读 `common/eval.py` 一个文件。
- `models/` 每个文件只管模型结构 + 损失。**不许自己写评估**——这是保证协议不被偷偷改掉的硬约束。
- `runs/` 是**证据**。每跑一次就留一份 tsv + config，导师随时能对。

## 二、新增一篇论文的复现：三步

### 第 1 步：写模型文件（`models/xxx.py`）

只需要实现两样东西：

```python
class XXX(torch.nn.Module):
    def score_candidates(self, users, items):
        """users: [B]   items: [B, 100]   ->   [B, 100]
        这是协议接口：第 0 列是正样本，后 99 列是负样本。"""
        ...

    def bpr_loss(self, users, pos, neg):
        """返回 (loss, reg)"""
        ...

def train(args):
    ds = ML1M()                       # 共用数据
    ...                               # 模型自己定义
    log = Logger(os.path.join(args.out, 'xxx', args.tag, 'metrics.tsv'))
    for ep in range(1, args.epochs + 1):
        ...
        if ep % args.eval_every == 0:
            hr, ndcg = evaluate(model, ds, dev)     # 共用评估
            log.log(ep, hr, ndcg)
    return log.summary()
```

**不许做的三件事**：
1. 不许自己写评估函数（协议会漂）
2. 不许自己造数据切分（切分只有一份）
3. 不许自己起随机种子（统一走 `set_seed`）

### 第 2 步：注册（`run.py` 一行）

```python
MODELS = {
    'bpr_mf': 'models.bpr_mf',
    'ngcf': 'models.ngcf',
    'xxx': 'models.xxx',        # ← 加这一行
}
```

### 第 3 步：跑 + 汇总（两条命令）

```bash
python run.py --model xxx --epochs 300 --out runs
python common/report.py            # 自动把新模型加进结果表和柱状图
```

**从"决定复现"到"结果进表"：读论文 2 小时 + 写代码 1–2 小时 + 跑 30 分钟。**

## 三、命名与归档规则

| 项 | 规则 | 例子 |
|---|---|---|
| 结果目录 | `runs/<model>/<tag>/` | `runs/ngcf/run1/` |
| tag 含义 | `run1` 主结果；`seed42/2024/7` 多 seed；`smoke` 冒烟 | `runs/ngcf/seed2024/` |
| 日志格式 | `epoch \t HR@10 \t NDCG@10`，6 位小数，**只追加不改写** | — |
| 配置 | 每次运行自动写 `config.json` | 含 dim/lr/reg/bs/epochs/seed |
| 图 | 一律由 `report.py` 生成，**禁止手改 png** | 改数字 → 重跑脚本 |

**为什么禁止手改图**：导师问"图是不是自己画的（意思是编的）"，你可以当场改一个 tsv 里的数字、重跑脚本、图跟着变——这就是答案。

## 四、当前覆盖（每篇论文对应哪个文件）

| 论文 | 模型文件 | 类型 | 状态 |
|---|---|---|---|
| NCF (WWW 2017) | `NCF-reproduction` 仓库（独立） | 集合 | ✅ 8 月完成 |
| LightGCN (SIGIR 2020) | `models/lightgcn.py` | 图 | ✅ |
| SASRec (ICDM 2018) | `sasrec/` | 序列 | ✅ 3 seed |
| **BPR-MF (UAI 2009)** | `models/bpr_mf.py` | 集合·强基线 | ✅ 本轮新增 |
| **NGCF (SIGIR 2019)** | `models/ngcf.py` | 图 | ✅ 本轮新增 |
| BERT4Rec (CIKM 2019) | `models/bert4rec.py` | 序列 | ⬜ 下一步 |

**为什么先补 BPR-MF**：「NCF vs MF Revisited」(2020) 的结论是简单 MF 不输 NCF。**不跑这个基线，你无法回答"神经网络到底赢没赢"**——而这正是导师最爱问的一句。跑完之后，你的表里就有 BPR-MF 和 NeuMF 并列，答案自己浮出来。

**为什么接着补 NGCF**：它是 LightGCN 要删掉的那一半（W 和 σ）。两个模型成对出现，"少即是多"这条结论才有实测支撑。

## 五、同步到 GitHub

`github.com` 的 git 传输在国内常被重置（443 连不上），但 `api.github.com` 通常可用。用 Git Data API 推送：

```bash
# 脚本在 check-2026-10/push_via_api.py，改 ROOT 和 REPO 即可复用
python push_via_api.py
```

流程：`POST blobs` → `POST trees` → `POST commits` → `PATCH git/refs/heads/main`。
注意：**空仓库 `GET git/ref/heads/main` 返回 409 而不是 404**，要先 `PUT contents/xxx` 建一个种子提交。
