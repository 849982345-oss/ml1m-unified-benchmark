# 05 · SASRec —— Self-Attentive Sequential Recommendation（ICDM 2018）

## 一句话
**把你看过的电影当一句话，用"注意力"判断下一个该看什么。**
和前面几个最大区别：它建模**顺序**，前面的模型都把历史当"一堆东西"。

## 怎么跑
```bash
cd C:\research-training\check-2026-10\code\SASRec.pytorch\python
python main.py --dataset=ml-1m-all --train_dir=seed42 --num_epochs=200 --seed 42
```
约 2 分钟（比图模型快很多）。每个种子一个结果文件，本文件夹 `results/` 里有 3 个。

## 结果（3 个随机种子）

| seed | HR@10 | NDCG@10 |
|---|---|---|
| 42 | 0.8300 | 0.5973 |
| 2024 | 0.8276 | 0.5970 |
| 7 | 0.8310 | 0.5986 |
| **均值 ± 标准差** | **0.8295 ± 0.0014** | **0.5976 ± 0.0007** |

论文报告：0.8235 / 0.5958 → **差 +0.006，千分位内，复现成立。**

三个种子的极差只有 0.0033，远小于模型之间的差距（0.115）→ **结论不是运气。**

## 我读出来的结论
1. **序列 ≫ 图 > 集合**。SASRec 比 NeuMF 高 13.9 个点 HR，比 LightGCN 高 11.5 个点。
   这个差距不是调参能补的，是**建模方式**的差别。
2. 在 ML-1M 这种中等密度的数据上，**"顺序"比"高阶协同"更值钱**。
   这条判断的边界在哪，是我下一步想验证的问题。
3. **一个协议细节**：SASRec 官方代码评估时是"每次随机采 100 个负样本"，
   而 NCF 用的是固定的一份候选文件。两种口径下它的 NDCG 差 0.0075 —— 
   所以我在 `repro-benchmark-ml1m/sasrec/eval_fixed.py` 里补了一次固定候选的复评。

## 局限（方法本身的）
- 只用用户自己的序列，用不到别人的协同信号（稀疏用户上最致命）
- maxlen=200 硬截断，长历史丢信息
- 绝对位置编码，不区分真实时间间隔
- 冷启动失效
