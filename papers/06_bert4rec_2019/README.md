# 06 · BERT4Rec —— Bidirectional Encoder（CIKM 2019）

## 一句话
**把 SASRec 的"只能看左边"改成"两边都能看"**，训练方式改成"把序列中间挖空让你填"（完形填空）。

## 怎么跑
```bash
python run.py --model bert4rec --epochs 200 --dim 64 --layers 2
```
约 2 分钟。跑 1000 轮用 `--epochs 1000`（结果在 `results/` 里已有）。

## 结果

| 指标 | 我的数 | best epoch |
|---|---|---|
| HR@10 | **0.7785** | 650 |
| NDCG@10 | **0.5669** | 650 |

## 我读出来的结论 —— 这是一个诚实的失败

**它没跑过 SASRec（0.8311 vs 0.7785，同一口径下差 5.3 个点），而且我跑了 1000 轮也没追上。**

最可能的原因不是模型结构，而是**训练目标**：
- SASRec 每一步只要求模型回答"这个物品 vs 一个随机物品，哪个更可能" —— **二分类**，好学
- BERT4Rec 要求模型在 **3,708 个物品里做全分类**（softmax）—— 在 ML-1M 这种规模上明显更难收敛

证据：650 轮达峰后不再上升，说明不是训练不够。

**这个结果比"复现成功"更值得讲**：它说明在同一份数据、同一套协议下，
**训练目标的选择可能比模型结构更影响结果**。

下一步：要么改成负采样二分类（但那就不是 BERT4Rec 了），要么按论文补一轮超参搜索。

## 局限（方法本身的）
- 全库 softmax 在数据量小时收敛慢
- 推理要做"掩码-预测"，比单向模型慢
- 双向注意力对"预测下一个"这个任务其实有信息泄漏的边界问题
